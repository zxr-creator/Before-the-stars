# v0.8.1 diplomacy written-contract addendum

This lists changes required by the next machine protocol; no JSON schema, SDK or implementation was changed. [Communication rules](../design/29-diplomacy-communication-v0.8.1.md) and the [agent protocol](../technical/02-agent-protocol.md) define full semantics. Historical v0.1/v0.2 JSON cannot certify this version. These limits continue in v1.0, subject to its four-seat product scope.

## Phases and public observation

- Add `contact`: simultaneously submit a set of at most three known counterparts. Mutual selection opens this round's channel. Set ordering has no meaning, contains no text, and cannot be changed during the round.
- Negotiation uses five simultaneous windows, 0–4; plan is separate. Outside negotiation, `negotiation_window = null`. Plan-signature scheduling uses internal window index 5.
- Observations include own selection, this pair's channel, combined used/remaining ten-envelope quota and current send permit. Other lists and undelivered message contents stay hidden. Pair counts are explicitly public match metadata for that pair.
- Add `diplomacy` queries for already visible records. Distinguish claims, relays, actual sources and referee-certified facts. Do not expose `is_lie`.

## Actions and envelopes

Adding `select_contacts` brings the action set to nineteen. Each `message`, `propose_treaty` or `sign_treaty` is one counted envelope, optionally containing text and legal evidence references. Each direction sends at most one per negotiation window; plan allows at most one new signature per pair. An envelope contains at most one formal operation, 2,000 Unicode scalar values of text, eight clauses, eight existing attachment references and 16 KiB of canonical payload. Fan-out expands per recipient pair and validates atomically.

`sign_treaty` is legal in negotiate or plan and names an actually known exact version. It immediately reserves the signer's committed assets. Ending chat does not form the contract. Multilateral versions fix `anchor_seat`, `anchor_confirmation_peer`, necessary signers and registration place. Ordinary members send their new signature to the anchor; the anchor sends its own to the fixed confirmation peer. Both count against the corresponding pair. Other parties that received the same version get only fixed registration notices. Actual arrival, all necessary consent and asset conditions remain governed by the contract state machine.

A legally created own version is known once its exact handle exists. Signing also sends a fixed signature-record copy to the specified registry, without free text or an additional chat counterpart. Both routes have real delivery costs, delay and receipts, but reserve the assets only once. Negotiation commitments stay locked across windows and cannot be reused in plan. Only actual registry receipt satisfies registration; anchor receipt is not registration.

`withdraw_offer` can use the protected path in negotiate or plan. `break_treaty` and `respond_contract` remain plan actions. These and real automatic performance use no new chat quota and need no current mutual selection. They permit only fixed operations valid for existing states, necessary evidence and resources, with no free text, new terms, arbitrary titles or new quote. Repeating an already effective change cannot send another notice or refresh a deadline.

## Atomicity and errors

Each pair shares ten envelopes. At a window's start, if at least two remain, each direction gets one permit. If one remains, allocate it by the opening public seat order and parity of `round + window`. An unused permit consumes nothing and is reassigned next window. Network arrival cannot win a race for the final slot.

Consume quota only on successful sealing and first insertion into the outgoing queue. A syntax, authority, visible-budget or quota precheck failure leaves the whole batch unsealed. Bind idempotency keys to canonical payloads; retries return the original receipt. Transit loss, withdrawal, expiry and arrival in a later round neither refund nor charge again. Reconnection restores counterpart selection, window permits, sent envelopes and signature reservations rather than granting another attempt.

New public errors: `CONTACT_LIMIT`, `CHANNEL_NOT_OPEN`, `PAIR_LIMIT`, `SEND_PERMIT_REQUIRED`, `MESSAGE_TOO_LARGE`, `FORMAL_PAYLOAD_REQUIRED`. They depend only on known rules and own pair quotas. Unknown/unauthorized targets still receive uniform refusal, without leaking other lists, in-transit signatures, geography or process truth.

## Migration and acceptance

P0 raises machine `protocol_version` and updates Rust DTOs, schema, TypeScript SDK, human UI and agent adapters together. Old fields/window batches cannot silently acquire new semantics.

Test both parties contesting the last slot, a fourth counterpart, group splitting, one controller using multiple identities, signature reservations competing with plan budgets, disconnected retries, old arrivals, refusal to chat blocking legal exit, multiround five-party signature fixtures, text/attachment payloads and secret projection. Five-party fixtures test general contract machinery; they are not a selectable v1.0 match size. Counting tests do not replace contract or isolation tests. Observed offers, production, war and performance still support legitimate inference; the prohibited behavior is extra arbitrary communication or fabricated authority.
