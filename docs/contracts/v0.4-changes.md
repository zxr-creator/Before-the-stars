# v0.4 written-contract migration

Historical written migration; current overrides are in the [v1.0 addendum](v1.0-design-addendum.md). No schema, Rust/TypeScript implementation or executable fixture was added at this stage. v0.1/v0.2 JSON remained historical. [v0.3 changes](v0.3-changes.md) retained only semantics not superseded here. The historical target envelope version was `0.4`.

| Area | Change and validation |
| --- | --- |
| Reward and completion | Ordinary seat packages do not reveal reward formulas, FTL fields or hidden objective types early. Once discovered, project known acceptance tasks/evidence. Training storage separately records full-victory reward, termination and truncation |
| Metric views | Generic MetricView includes unit, scope, period, observation/receipt times, source, quality, coverage, value/range and revision. Metric names cannot expose hidden social parameters |
| Queries | Add `metrics` and `series`, explicit time/entity/product scope and pagination, bound to observation_id. Culture queries do not return eight axes |
| Population views | Separate ages, births/deaths/migration and registration revisions. Schooling, care, health and family surveys obey report access; no private pregnancy-person list or true decision coefficients |
| Military views/projects | Distinguish called, actually present, training, qualified, deployed, casualties, captured, missing and demobilized. Recruitment, training, reorganization and officer education use known templates; deployment/retreat use military_order |
| Military task fields | `transfer / assault / prepare_defense / escort / interdict / rest / demobilize`; select authorized known `cargo_ref / connection_ref / return_node_ref`, `target_priority_refs`, `local_contingencies`, `retreat_thresholds` as applicable |
| Military project scale | Fixed template sizes, no arbitrary target_people. Sources, candidates, formations and posts use permitted choices; actual staffing is limited by the intersection of all resources |
| Contract views | Separate Offer, Obligation, Custody and Claim. Show learned states/dates, not current hidden truth disguised as a distant receipt |
| Obligations | Guarantee kind (delivery/service/result), batching, acceptance authority, fees, cure/dispute windows, final closure month, risk allocation, exit and future-stage rights |
| Collateral settlement | Noncash collateral specifies `settlement_unit_value, max_quantity`; offset claims at presigned value, not omniscient prices or rounding-created cash |
| Personnel in peace terms | `captive_releases` identifies known detention records, quantities, release place/date, transport and reception duties. People are not goods_delivery products; release does not restore military qualification automatically |
| Signature locks | Expiry does not directly unlock assets. Release requires executable evidence; late messages cannot execute twice. Local reservations and actual remote custody remain separate |
| respond_contract | New plan action: `treaty_ref, obligation_ref, operation, evidence_refs`; operation-dependent batch, quantity/amount, bounded reason, cash cap and real asset/service references |
| Contract operations | Only `accept_delivery / submit_evidence / dispute / cure / terminate_notice / authorize_release`; separately validate rights, evidence and resources. Errors do not reveal hidden liability truth |
| Action set | Historical total: 18 types, with eight treaty types. No direct population/culture editing or automatic research-completion action |
| Known contingencies | Bounded signing responses, local supply/retreat and standing purchases read their organization's known information; no arbitrary referee scripts |
| RL trajectories | Separate actor observation and private referee/critic fields; explicit elapsed_months, action_ref, receipt_ref, terminated, truncated, terminal reason, policy_version and opponent_version |

The interface should clearly show legal operations in a known state; the expected social reaction is not directly preflighted. New contract enums cannot leak undiscovered agreements, and military states do not expose enemy rosters.

Future legal/illegal fixtures must include primitive in-kind construction, registration revision, duplicate personnel use, cross-group training, remote signing, partial acceptance, buyer obstruction, diligent research failure, misappropriated evidence, custody failure, duplicate release, joint-research withdrawal, conquest without FTL, interrupted military capability, quitting, training truncation and early reward leakage. Reviewable text does not mean these tests have run. Population details are subsequently simplified in v1.0 without removing conservation or information restrictions.
